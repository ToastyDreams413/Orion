Technical overview

Orion system design

A simulation-first defense dashboard that turns object motion, sensor signals, ML predictions, and rule-based scoring into an explainable operating picture.

◎

Purpose

Modern wars are shaped by fast drones, missiles, aircraft, and ambiguous signals. Orion asks a simple human question: when the screen fills with tracks, what should an analyst look at first, and what evidence supports that call?

Architecture

  • Frontend: vanilla JS dashboard with 2D canvas, Cesium 3D globe, object inspection, event log, and advisor chat.
  • Backend: FastAPI serves state, scenario settings, response logging, project Q&A, and advisor endpoints.
  • Scoring: interpretable risk components are computed in C++ when built, otherwise by an equivalent Python fallback.

AI / ML layer

  • Isolation Forest: flags tracks whose feature vectors look unusual for the current scene.
  • Random Forest: predicts likely object class and provides an optional trained advisor-policy second opinion.
  • Grounded LLM advisor: when configured, receives a compact live-state packet and writes the commander-facing answer.
  • KMeans: groups behavior patterns such as direct approach, loitering, pass-by, and high-altitude transit.

Advisor logic

  • Computes deterministic playbook guidance first, then uses an LLM for stronger conversational synthesis when an API key is present.
  • Ranks the full scenario or focuses on a named track without requiring a dropdown.
  • Answers broad questions like “what matters now?” and specific questions like “what does capability on A1 mean?”
  • Recommends simulated options such as monitor, identify, communicate, dispatch patrol, advisory, or intercept workflow.

Explainability and safety

  • Every recommendation is tied back to visible scores, sensor evidence, and the deterministic fallback answer.
  • The app is a portfolio simulation only; it does not control real systems.
  • The goal is analyst decision support: prioritize, explain, and reduce uncertainty.

Motivation and goals

  • Build an end-to-end pipeline from object state to visible operator output
  • Expose intermediate reasoning instead of only returning a final label
  • Support a readable guided mode and a deeper technical inspection mode
  • Make the scene easy to perturb through scenarios, environment changes, and test-object injection

How I think about Orion

Orion is an interactive threat-detection and analysis system. It can also be viewed as a prototype decision-support agent because it interprets tracks, combines evidence, and explains its conclusions.

Pipeline

  1. Instantiate scenario tracks with class, state, and environment context
  2. Advance each track through simplified motion logic and altitude behavior
  3. Synthesize raw and proxy sensor readings for every track
  4. Compute derived kinematic, geometric, and contextual features
  5. Fuse rule-based threat logic, ML outputs, and public-signature matches
  6. Render interpreted state in 2D/3D and emit event messages

AI / ML in Orion

  • Isolation Forest: scores how abnormal a track looks in the current feature space
  • Random Forest: predicts likely object labels from the multi-signal feature vector
  • KMeans: groups similar movement patterns to expose behavior clusters
  • Feature importance and probabilities: surface why the model leaned toward a given interpretation

The ML layer is used as a supporting analysis channel, not as a black-box replacement for the interpretable threat logic.

Public-data-informed matching

Public reference profiles are treated as supporting evidence, not absolute truth. Orion compares observed readings and derived behavior against reference signatures, scores the best match, and exposes the comparison in the Catalog tab.

Physics and environment

  • Object classes occupy different motion and altitude regimes
  • Wind, hazards, visibility loss, and jamming directly affect sensor quality and confidence
  • Distance-to-zone, closing speed, CPA, and TTZ are computed from propagated track state
  • The 3D globe shows visible-side tracks, US protected airspaces when zoomed in, and stronger highlighting for missiles, unknowns, and foreign/anomalous contacts

Best tabs to inspect

  • Sensors: raw and derived readings
  • Analysis: threat logic, ML, and clustering
  • Catalog: signature matches and source evidence
  • Model: the major analysis layers involved
