Why I Built Orion

Turning abstract fear into a system: visible and explainable danger

This closing deck summarizes the implemented pipeline: simulation, tracking, sensor fusion, ML scoring, live-data enrichment, and grounded advisor reasoning.

Implementation Architecture

1

Simulation + Tracking

  • FastAPI state API drives the browser simulation loop
  • Scenario manager emits 9 event families: drone swarm, ballistic approach, orbital debris, asteroid pass, and more
  • Physics propagation updates position, velocity, altitude, heading, and predicted path each tick
  • Kalman-lite tracking smooths noisy observations into stable track estimates
2

Sensor Fusion + Data Enrichment

  • Simulated radar, optical, thermal, radiation, plume, transponder, and jamming signals
  • Noisy sensor fusion creates confidence, dropout, uncertainty, and evidence fields
  • Live/context sources: OpenSky aircraft, CelesTrak orbital objects, NASA/JPL small-body data
  • Signature-matching catalog enriches tracks with known object families and expected behavior
3

ML + C++ Scoring Core

  • Feature vector: directness, CPA, TTZ, zone hit, closure, anomaly, uncertainty, and environment
  • Python ensemble: IsolationForest, RandomForestClassifier, KMeans, and policy-action classifier
  • Deterministic C++ scoring engine combines intent, capability, environment, anomaly, and confidence
  • Escalation rules raise scores for high-consequence classes and near-term zone intersections
4

Grounded Advisor + UI

  • 3D globe, labels, selected-track panel, score breakdown, sensor evidence, and logs
  • Advisor builds a ranked JSON packet from live state instead of answering from memory
  • RAG-based Q&A retrieves project/system context for architecture questions
  • Scope enforcement keeps answers tied to selected tracks, scenario state, and allowed response categories

Current AI / ML components

IsolationForest scores abnormal behavior from speed, directness, TTZ, uncertainty, radiation, thermal, swarm, and transponder features.

RandomForestClassifier classifies tracks as benign, suspicious, or critical from the fused feature vector.

KMeans groups motion/signal patterns so the UI can describe behavior families, not only raw scores.

Policy model maps a 19-feature advisor vector to monitor, increase tracking, identity check, advisory, patrol, civil protection, intercept workflow, or stand down.

Live enrichment adds OpenSky/CelesTrak/NASA-JPL-style context and signature matches into the same evidence packet the models and advisor use.

C++ scoring core turns model outputs and deterministic thresholds into the final ranked threat score.
